## Session 1 — Where we are, and whether it is real

- Recap after two days away. Everything committed and pushed; the Render site is live and
  redeploys on every push.
- Owner's questions: is the plan good, is it achievable with this stack, can the film room's
  output really come from video alone? Answers written up in the chat and in the decision log's
  spirit: yes with named risks; field registration is the one that decides it.
- Fact from the owner: All-22 film shows no painted first-down or scrimmage lines. Registration
  now anchors on the painted yard numbers plus the official line of scrimmage, two independent
  anchors that must agree.
- New process: a "Right now" block on the Now page, fed by a small file and a one-line command
  that logs a step and pushes it, so the site moves in baby steps during a session rather than
  at the end of one.

## Session 2 — Teaching it where it is wrong

- Owner's question: when the model is wrong, will there be an edit mode to correct it, and was
  that planned for? It was not, explicitly. Designed now: corrections as first-class, versioned
  hand labels with the machine value kept beside them; correctable at label, identity, event,
  position and whole-play level; a "this is wrong" flag when the fix is unknown; corrections feed
  evaluation, retraining and rule changes; a re-run never touches a reviewed play. Blueprint
  section 9.5, decision D-021, three new stories. The editing UI waits for real output.

## Session 3 — Getting film in, and going live

- Owner's questions: can I just drop a file into a game and press a button, and what if we want
  to go live one day, maybe with only one camera? Designed both now. Ingestion: new game from the
  schedule, drop film, an automatic film window, a check screen that compares the play count
  to the official list before anything expensive runs, one Analyze button, plays filling in as
  they finish. Live: a live pass from a single angle seconds after the whistle, then a post pass
  that upgrades the record field by field when the full film arrives. Three interfaces are
  decided today so nothing gets reworked: file-or-stream sources, play boundaries from the play
  itself rather than camera cuts, and fusion that accepts one angle or two. Blueprint section
  11, decision D-022, milestone 10, stories GRD-83 to GRD-92.

## Session 4 — Closing milestone 0

- Owner asked whether planning was done. It is: blueprint, play record contract, correction
  loop, ingestion and live design, tracker, film room demo, every open decision answered.
  Closed at 100%. The mobile pass and the edit mode moved to the film room milestone; the NFL
  API credentials item moved to milestone 1, where it is needed. Milestone 1 is now active and
  its first step is the Python runtime.

## Session 5 — Milestone 1, nearly all of it

- Runtime: uv installed without Homebrew, Python 3.12.14, the environment rebuilt, one test
  updated for pandas 3. All green.
- Ingestion: one frame-source interface with file and stream implementations; a probe that
  writes a sidecar; a 540p proxy that stays frame-aligned with the source; per-play clips for
  both angles with a manifest back to the source frame; and film-window detection that finds
  the coaches film inside a screen recording by how much of each frame is turf. All tested on
  synthetic video, so none of it waited for the real film.
- NFL API: the client ported with the same discipline as the reference (cached token, one 401
  retry, a freshness floor), adapters for game detail, rosters and teams, the GSIS stat-type
  table, and fz-nfl. Tested offline; live payloads wait for the credentials.
- A real fix found on the way: kicks, punts and kneels were not being numbered, so the free
  play list had 183 plays against 184 on film. They are now, and the counts match exactly.
- The play record contract: closed vocabularies, JSON Schema v1 generated from them, a
  validator, and a record for every one of the 184 plays from official data alone. fz-export
  writes a game as JSONL. A client can integrate today.
- The runner: manifests fingerprint inputs and config; fz-run skips what is unchanged.
- 201 tests. One milestone 1 item left, and it is the credentials.

## Session 6 — The NFL API, live, and milestone 1 closed

- The owner supplied the credentials. First live calls: token exchange, the playoff slate (week
  20 is postseason round 2, as assumed), the Rams–Bears game detail, both rosters.
- The real payload corrected three assumptions at once: the drive chart carries bookkeeping
  rows (game start, end of quarter, end of game) that must never count as plays; the NFL spells
  the Rams "LAR" where the free data says "LA", which would have flipped the line of scrimmage
  on every Rams possession; and jersey numbers arrive zero-padded. All fixed, all tested.
- Then the good news: 184 filmable plays on both sides, identical order, and every one of the
  free data's play ids exists in the NFL payload. Labels now merge by exact play id. The play
  table is the NFL API's, with the free formation and personnel labels joined on.
- Every record now carries who touched the play with jersey numbers, the NFL game id and the
  GSIS id. Milestone 1 closed at 100%. 209 tests.
